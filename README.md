# finance-mcp-demo

An MCP server that turns a company's messy finance exports into clean, agent-ready data, so an AI agent (for example Claude) can answer questions like *"What is our burn rate and runway?"* with numbers it can explain.

Built as a small, realistic version of a common onboarding problem: every customer sends data in a different shape, and an agent is only as good as the data and context it gets.

> The company in the sample data, *Nordlys Analytics AB*, is fictional. All data is generated by `scripts/generate_sample_data.py`.

## What it does

```
data/raw/stripe_payments.csv  ─┐
                               ├─►  ledger.py  ─►  clean ledger  ─►  analysis.py  ─►  server.py (MCP tools)  ─►  Claude
data/raw/bank_transactions.csv ┘    (clean + quality report)          (metrics)
```

1. **Clean** two raw sources into one ledger with the same columns: `date, month, source, type, category, description, amount_sek`.
2. **Report** every fix and exclusion in a data quality report, so nothing changes silently.
3. **Serve** a small set of well described tools over MCP.

## Data problems it handles

| Problem in the raw data | What the pipeline does |
|---|---|
| Stripe amounts in minor units (`450000` = 4 500 SEK) | Divides by 100 |
| Mixed currencies and casing (`sek`, `SEK`, `eur`) | Standardizes codes, converts EUR to SEK |
| Failed and refunded payments | Excludes them from revenue |
| Swedish number format (`-12 345,50`) | Parses spaces, comma decimals, unicode minus |
| Mixed date formats (`2026-01-05` and `05/01/2026`) | Normalizes both |
| Duplicate bank rows (sometimes with different date formats) | Removes them *after* normalizing, so they are actually detected |
| Stripe payouts arriving in the bank | Excludes them, otherwise revenue would be counted twice |
| Expenses with no matching category | Marks them `uncategorized` and lists them in the report |

## MCP tools

| Tool | Answers |
|---|---|
| `get_data_quality_report` | What was cleaned, fixed or excluded. The agent is told to check this first. |
| `get_monthly_summary(from_month, to_month)` | Revenue, expenses and net per month |
| `get_expense_breakdown(month)` | Expenses by category with share of total |
| `get_burn_rate(months)` | Average monthly burn over the last N months |
| `get_runway(cash_balance_sek, months)` | Months of runway at the current burn |
| `get_revenue_growth()` | Month over month revenue growth |

Every result includes a short `method` or `note`, so the agent can explain how a number was calculated. Invalid input (for example `from_month="August"`) returns a clear error message instead of crashing.

## Quickstart

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
python scripts/generate_sample_data.py   # optional, sample data is already included
pytest                                   # 7 tests
python scripts/smoke_test_client.py      # starts the server over stdio and calls the tools
```

### Use it from Claude Desktop

Add this to `claude_desktop_config.json` (Settings, Developer, Edit Config), using the full path to the Python in your virtual environment:

```json
{
  "mcpServers": {
    "finance-data": {
      "command": "/full/path/to/finance-mcp-demo/.venv/bin/python",
      "args": ["-m", "finance_mcp.server"]
    }
  }
}
```

Restart Claude Desktop and try:

- *"Give me a short financial overview of the company. Mention any data quality caveats."*
- *"What is our runway if we have 1.5 million SEK in the bank?"*
- *"Which expense categories grew the most between July and September?"*

To point the server at other data, set `FINANCE_RAW_DIR` to a folder with the same two files.

## Design decisions

- **Clean before the agent sees anything.** The agent gets one consistent ledger, not raw exports, which makes answers repeatable.
- **Deterministic code for numbers, LLM for explanation.** Sums, burn and runway are plain Python. The model decides which tool to call and explains the result.
- **Transparency over magic.** Category rules are simple keyword rules, and anything they cannot match is surfaced, not guessed.
- **Small, focused tools** with clear descriptions instead of one tool that runs arbitrary queries.

## What I would add next

- A config file per customer for column mapping, so a new data source does not need new code
- Daily FX rates instead of a fixed EUR rate
- An LLM-assisted suggestion step for uncategorized transactions, with human approval
- An evaluation set of questions with expected answers, run against the agent end to end
